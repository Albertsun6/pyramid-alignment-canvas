## 产品改造方案 A：检索优先（先不开发版）

### 1. 信息架构（IA）

目标：把“方法论推荐”从生成式改为“可检索、可解释、可回退”。

页面结构建议：

1) 方法论层主页面（第 2 层）
- 约束摘要区：展示从上层抽取的结构化约束（领域、问题类型、证据偏好、时间/团队约束）
- 检索控制区：重新检索、放宽约束、切换排序方式
- 候选列表区：Top N 推荐（默认 5 条）
- 决策区：主方案 + 备选 + 一键应用
- 失败兜底区：低置信度时引导“放宽再搜 / AI 定制”

2) 方法论详情抽屉
- 方法论说明、适用边界、风险、来源、步骤模板
- 匹配解释（命中项/冲突项）

3) 反馈闭环
- 用户动作记录：查看详情、选中、应用、反悔重选
- 用于后续权重调优


### 2. 结果卡片字段定义

每张推荐卡片应包含：

- 基本信息：`name`、`origin`、`category`
- 匹配指标：`matchScore`（0-100）、`confidenceLevel`（高/中/低）
- 解释信息：
  - `fitReasons`：适配理由（最多 3 条）
  - `conflicts`：冲突点（最多 2 条）
  - `riskNote`：主要风险（1 条）
- 应用信息：`stepsPreview`（简要步骤）、`evidenceType`（定量/定性/混合）
- 交互按钮：`设为主方案`、`加入备选`、`查看详情`

建议分组展示：
- 75+：高匹配（优先）
- 55-74：可用但有冲突
- <55：低匹配（默认折叠）


### 3. 评分规则说明书（V1）

#### 3.1 输入

- 上层约束结构化结果：
  - 领域（domain）
  - 问题类型（problemType）
  - 证据偏好（evidencePreference）
  - 确定性偏好（certaintyPreference）
  - 团队规模（teamSize）
  - 时间窗口（timeHorizon）

- 方法论库元数据：
  - 适用领域、适用问题类型、资源要求、证据属性等

#### 3.2 评分公式（规则版）

`matchScore = 0.30*domain + 0.25*problemType + 0.20*evidence+certainty + 0.15*resource + 0.10*history`

各子分范围 0-100，最终取整。

#### 3.3 判定阈值

- `>=75`：高匹配，允许直接推荐为主方案
- `55~74`：中匹配，要求展示冲突说明
- `<55`：低匹配，不推荐直接应用

#### 3.4 可解释要求

每个候选必须产出：
- 命中项（至少 2 条）
- 冲突项（至少 1 条，若存在）
- 风险提示（至少 1 条）


### 4. 低置信度流程与文案模板

#### 4.1 触发条件

- Top1 分数 < 75，或 Top3 平均分 < 65

#### 4.2 流程

1) 提示当前结果为“低置信度”
2) 提供两个路径：
- 路径 A：放宽约束后重检索
- 路径 B：基于当前约束创建 AI 定制方法论
3) 若走路径 A：给出可放宽项建议（最多 2 项）
4) 若走路径 B：明确标注“AI 定制，非标准已有方法论”

#### 4.3 文案模板

- 标题：`当前没有高置信度的现有方法论`
- 描述：`已检索到 {n} 个候选，最高匹配分 {topScore}。建议先放宽约束再检索，或使用 AI 定制方案。`
- 按钮：
  - `放宽约束再检索`
  - `创建 AI 定制方法论`
- 说明：`定制方案会标注参考来源与适用边界，便于后续验证与迭代。`


### 5. 验收指标（产品评审用）

- 候选返回率 >= 95%
- “无结果”提示率 <= 10%
- 首次应用率 >= 70%
- 推荐后回退率 <= 25%
- “推荐理由清晰度”用户评分 >= 4/5
